# v2.6.1 原生宿主补测步骤

适用对象：`yq6666-66/408-codex-plugin`，候选提交 `c1d632a2059ff1bce26eb5643fa5c95d12b92edc`，版本 2.6.1。当前首次结果见 [报告复核](native-host-review-20261017.md)。本步骤供实际客户端操作与采集，不宣称完成了尚未运行的测试。

## 先确认来源和会话

记录客户端版本、模型、操作系统、安装入口、插件版本、能确认的提交或安装树摘要。无法显示的字段写“无法确认”。用户账户、登录凭据不属于验收材料。

安装树可用仓库里的只读命令核对；把占位符替换为真实已安装目录，不要把源码目录当作安装目录：

```powershell
python scripts/install_local.py verify-tree --dir "<已安装插件目录>" --version 2.6.1 --tree-sha256 17e514cb484449485eb846fc55d93220a9ec1a8f9d14ab62934a577b2b2dbcea
```

该命令只证明安装文件版本和完整性。安装或启用后，用重载/重启后的新会话检查技能是否可见；不能从旧会话没有技能推断新安装失败。

本机和云端分别记录。客户端无法创建新会话、无头 CLI 缺登录态、界面无法确认版本等，标记环境受阻或无法确认，不以静态检查代替。

## 优先补测顺序

1. **ZCode**：保持首次测试模型和版本，在新会话通过 UI 实际选择 `@408考研插件`，提交下面的计算题。记录该操作是“显式选择”。若只键入普通文本而未选择界面中的插件，也须注明。
2. **WorkBuddy**：重载/重启后新建会话，先直接提交计算题，记作“普通请求”。若没有选择技能，再用另一个新会话通过客户端确有的插件选择入口做对照。不要猜测不存在的 slash 命令。
3. **Cursor**：先保存本机 Customize 的来源/版本或安装记录，再在本机新会话提交计算题。已有云端子会话数据单独保留。
4. 关键链路采集后，补齐下方其余三个请求，每项使用独立新会话。

一次对照只改变“是否显式选择插件”，其余题面、模型、插件版本保持一致。模型变化或增加“请读取某个 Skill”等指令时，单列另一轮，不能覆盖首次结果。

## 发给被测会话的请求

普通请求测试只发送对应题目，不粘贴本说明、预期 Skill 名、评分标准或 SKILL.md 正文。保持正常客户端技能发现环境。显式选择测试在相同题目前加实际的 UI 插件选择。

### 计算题

```text
3 个页框，初态为空。用 FIFO 校验引用串 1,2,3,4,1,2,5,1,2,3,4,5，给出每步页框、命中或缺页、淘汰页，以及最终统计。说明是脚本核验还是人工复核。
```

### 概念追问

```text
FIFO 和 LRU 有什么区别？为什么 FIFO 命中后不调整淘汰队列？
```

### 错题归因

```text
我的解题过程是：FIFO 中页 1 命中后，我把它移到队尾，因为它刚刚被访问，所以应该最后淘汰。请指出我第一处错误，解释原因，再给一道最小验证题，先不要公布验证题答案。
```

### 提示边界

```text
3 个页框，初态为空，引用串 1,2,3,4。使用 FIFO。我已经完成前三步，只给第四步的思考提示，不要直接给出淘汰页或最终页框。
```

## 观察与记录

保留首次请求、完整回答，以及界面可见或可导出的工具轨迹。失败和重试单独保存；不采集隐藏推理，不以 Agent 自述代替可见调用证据。

| 项目 | 记录方式 |
| --- | --- |
| 来源 | 提交/安装树与证据路径；未知则明确未知 |
| 技能发现 | 名称、可见列表/输入摘录；文件存在不等于会话注册 |
| 调用 | 客户端的 Skill 加载记录、文件读取路径或等价可见事件；看不到时写无法确认 |
| 共享引用 | 实际读取的引用路径；仅磁盘可读另记文件系统检查 |
| 计算工具 | 实际命令、脚本路径、退出状态、原始输出；区分随包模拟器与独立临时代码 |
| 回答 | 原始输出、是否遵守只提示/不公布验证题答案等约束；正确性由评分侧另核 |
| 受限 | 原始错误、该命令是否执行、回答如何说明限制 |

Skill 已加载但选择人工推导，与没有加载 Skill 是两种结果。当前契约允许人工推导，未运行脚本不能直接判定讲解失败；若要验证随包工具链，可另开“使用插件随包模拟器”的定向测试，单列结果。

脚本被守卫拒绝时保留拒绝记录，不关闭守卫，不通过改名、复制、内联或更换解释器绕过；是否按契约进行人工降级须从后续原始回答判断。直接手动执行脚本成功，不能代替 Skill 驱动工具的证据。

## 只读核对 ZCode 调用记录

已有 ZCode `parts.jsonl` 时，可从仓库根运行：

```powershell
python scripts/audit_host_trace.py --trace "<本次会话的 parts.jsonl>" --mode ordinary
```

`--mode` 必须如实指定 `ordinary`（普通请求）、`explicit`（显式选择）或 `tool-directed`（定向工具测试）。工具只读取轨迹与仓库技能目录名，向 stdout 输出带输入 SHA-256 的 JSON；不执行轨迹中的命令，不输出对话正文、命令内容或工具返回正文。

同一 `callID` 的多次状态快照只计一次，后续快照更新状态，省略的参数保留此前已知值；同一 ID 改换工具或非空 Skill 名称时拒绝统计并报冲突。用户引用的工具文本不计入助手实际调用，其他插件同名技能不计入本插件。`completed` 仅表示记录中的工具状态，不等于回答通过。空轨迹和格式错误会退出失败；正常解析退出 0 也不是行为验收通过，报告固定保留 `behaviorGrade: not_assessed` 和 `traceCompleteness: not_verified`。未记录调用只能说明在给定轨迹中未观察到，不能证明导出完整。

该工具目前仅支持 ZCode 的 role/part JSONL。Cursor 与 WorkBuddy 原始导出格式尚未取得，继续用原始材料人工复核，不把其他格式强塞进去。
