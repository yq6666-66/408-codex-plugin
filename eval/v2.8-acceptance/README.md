# 2.8 十组自然请求路由验收夹具

状态：`fixture-only`。这里提供 10 组 A/B、20 个 case、23 个自然输入轮次；没有运行被测模型，没有行为判分，也没有平台支持结论。

这里的状态仅指本目录 `cases.json` 的自动路由对照。另有 20 条知识点定向样本和 1 条工具定向样本，输入来自 2.7 验收集、运行于 2.8 集成树，见 [定向行为记录](directed-model-results.md)；它们不能替代这十组路由验收。421 项工程检查、51 文件产物与原生清单证据见 [开发记录](development-results.md)。

这些夹具落实 roadmap 6.3 的十组对照，预期依据当前的 `capability-routing-contract.md` 和 14 个 Skill 的主责边界。第 10 组保留同会话上下文；其余每个 case 在全新会话运行。A/B 不能串成同一个会话，以免前一个请求影响另一臂。

## 文件

- `cases.json`：自然请求与评分侧定义。**整个文件不能送给被测模型。** 每个 case 的 `turns` 是唯一允许直接发送的字段；多轮按原顺序发送。
- `materials/notes-vault/`：第 9 组的原创虚构 Vault，不是用户学习记录。
- `materials/obsidian-brain.template.json`：只供运行侧生成隔离配置，`vaultPath` 占位符必须替换为当前 case 的新 Vault 副本。
- `materials/notes-host-fixture.json`：隔离笔记宿主的准备要求与虚构 Notion store。它是固定种子定义；[本地 stdio 服务](NOTES_FIXTURE.md)已有工程与 SDK 互通检查，仍不是模型调用轨迹。
- `materials/notes-queue.json`：与 Vault 中内容对应的 `ReviewQueue 1.2` 原始夹具，便于结构验证；不要把它当另一条学习历史重复导入。
- `self-audit.json`：数据约束、重复与入口覆盖的静态自审，不是行为评分。
- `export_inputs.py`：按 case ID 导出白名单输入，不调用模型或自动评分。
- [tests/test_v280_inputs.py](../../tests/test_v280_inputs.py)：9 项输入投影、路径边界与 A/B/评分轮次/主责完整性检查，已接入现有离线门禁；外部最初的 8 项检查是历史记录。

## 输入和评分分开

运行工作区只放所需用户材料、已隔离的笔记夹具和正常安装环境。`cases.json`、本 README、`self-audit.json`、评分结果及原始运行输出应保留在模型不可读的评分目录，不能连同仓库整体暴露给模型。

模型依赖宿主正常的技能发现流程。不要在系统提示、`AGENTS.md` 或用户消息中指定预期 Skill、提供对应文件的强制读取指令，或贴入完整 Skill 正文。不能把 `reviewOnly`、组标签、预期知识点 ID、评分答案、`expectedPrimary` 或允许的后续 Skill 发送给模型。

现有 `eval/v2.6-acceptance/run_cases.py` 在工作区 `AGENTS.md` 中写入指定 primary Skill，并要求读取成功，因此它收集的是定向 Skill 执行，不能原样用于证明自动路由。可以复用其中的版本/产物核验、JSONL 采集、线程绑定、工具结果提取和前后文件快照；只移除路由泄露并接入这些自然输入，不另建一套自动评分系统。

`reviewOnly.perTurn[n]` 对应 `turns[n]`。`expectedPrimary` 是评分侧的单一主责；`allowedSecondarySkills` 仅允许符合条件的前置核验或同轮连续交接，并不意味着两个主责。`allowedClarifications` 允许真正改变结论的最小追问，不允许用追问替代已有信息足够完成的工作。

轻量接口：运行 `python -B export_inputs.py G10-B`，stdout 只包含 `messages` 和 `materials` 两个键。函数形式是 `export_case(catalog, case_id, material_root=...)`。`messages` 保持自然 user 消息的原文和顺序；运行器应逐轮发送并插入真实模型回复，不能把所有轮次一次性交给模型。`materials[].path` 相对本夹具目录，运行器据此把已验证材料复制到新工作区。第 9 组只输出 `notes-vault`；配置模板和 fake-store 准备定义不属于模型材料。

导出函数不会递归拷贝 case metadata，也不会生成答案或 assistant 历史。它拒绝自然输入中的 Skill/知识点标识和越界、别名路径；出错只向 stderr 解释、退出 2，stdout 留空。它不能自动判定任意自然句子是否包含评分答案，题面和已知用户过程仍需人工审阅。本批 20 个输入已经做过此项静态审阅。

## 第 9 组隔离条件

每个 A/B case 复制一份新的 Vault，并保存运行前文件集合与 SHA-256；不能共用 A 已运行过的 Vault。把模板配置放进已有授权、独立测试 home 的插件配置位置，验证 Vault 解析后的绝对路径仍在本 case 的夹具根目录内。不得改稳定用户配置，不读取或复制凭据，不连接真实用户笔记。

Obsidian 的文件能力要实际可用。Notion 只通过完全隔离的 fake store 暴露正常的搜索、读取、创建和更新能力，并记录调用；不能连到真实 Notion workspace。fake store 的唯一插件标记和页面层级应在运行前可读，确保“没有绑定”不成为预设的免写理由。不要用拒绝一切写入的工具冒充已测权限语义：需要能观察模型是否尝试了不被用户授权的写入，且任何尝试只能作用于夹具。

隔离 Notion 服务现已实现，见 [启动与证据说明](NOTES_FIXTURE.md)及[2026-10-19 工程验证](notes-fixture-validation-20261019.json)。这只补齐工具层，原生宿主隔离与 G09 模型运行仍未完成。

A 要求所有学习层只读：所有 Vault 原文件、文件集合和 fake store 应不变，且没有笔记写入调用。B 只禁 Notion 同步：Obsidian 中应有实际可回读的增量，保留稳定 ID、原记录和批注哨兵；允许在该隔离 Vault 内备份原文件、更新索引和日志。Notion 的 create/update/delete 调用仍应为 0。若工具并未实际隔离、配置不可用或宿主没有正常读取能力，标 `invalid-environment`，不要连接真实工具补测。

两臂的虚构记录都只提供观察与原因假设，没有独立延迟复测证据。按已有记录出现到期状态并不等于已经复测或掌握，不得自动补出 `mastered`。

## 采集与人工评分

每次采集记录候选版本、提交、精确安装树哈希、客户端/系统版本、模型、运行日期和时区、发现的 Skill、输入材料哈希、各轮线程 ID、公开可用的工具调用/结果及原始回答。源码或安装树改变后，旧树结果不能直接继承。只保存必要的公开消息和工具证据，不提取或发布隐藏推理、凭据或真实用户资料。

本夹具没有固定“今天”。涉及最近两个已完成招生年度、相对日期和复测日期时，以真实运行的可靠宿主日期/时区为基准并记录。提示中已给的 2026 年历史记录不得随运行日期重写。

评分至少分开两条轴：

1. 路由：看正常发现及实际 Skill 调用/完整正文读取证据与任务行动是否匹配，记录误接、漏接和不必要的接管。只有答案正确、模型自称“使用了某技能”或列出技能名，不能证明技能实际驱动。单纯读取很多 Skill 也不能自动证明选对主责。
2. 行为：按该轮 `must`、`mustNot` 和 `behaviorChecks` 人工审查教学、证据年度、来源真实性、提示泄题、笔记权限与保存状态。路由正确不能替代计算或事实正确。

每条轴分别用 `pass`、`fail`、`not-assessable`；采集状态另用 `not-run`、`captured-ungraded`、`invalid-environment` 等已有层次。未运行保留 `fixture-only`，不能预填 pass。宿主拒绝读取 Skill、技能描述因上下文预算被移除、认证失败、超时或无法隔离笔记，均需保留原始失败并按实际影响分类，不能为了拿到结果改名脚本、更换解释器或绕过守卫。

联网组允许诚实的来源未核结论；“有正确的主责读取证据”和“完成官方事实核验”分开评分。没有搜索发现工具或附件打不开时，不能凭记忆补出来源、年份、录取分数、题面或答案。

## 轻量数据约束

沿用现有测试方式做普通数据校验即可：20 个唯一 case ID，10 个唯一 group，每组恰有 A/B；`turns` 为非空字符串数组，`reviewOnly.perTurn` 与轮次数一致；主责和允许后续入口均属于候选的 14 个 Skill；每条 `executionStatus` 仍为 `fixture-only`；`materials` 必须存在且解析路径不越界；模型可见 turns 不含 Skill 标识或知识点 ID。不要建立一套根据关键词自动宣布行为通过的框架。

G10 的两臂共享第一轮是有意控制条件，其余完整输入不重复。G05-A 与 G07-B 都指向搜索入口，但分别测试“无题面寻找试卷”和“已有题面核真题身份”；G06-A/B、G08-A/B 故意维持同一入口，比较输出要求而不是强行要求换 Skill。

十组覆盖了 10 个主责入口：408 辅导、错题闭环、规划、执行、诊断、官方核验、招生研究、真题搜索、真题分析、数学辅导。英语、政治、材料整理和模考 4 个入口不在这十组主责样本中。这是本批覆盖边界，不代表它们有问题；不能用本批结果宣布全部 14 个 Skill 或任意自然请求均已通过。若以后扩大范围，为这 4 个入口另加小规模对照即可，不改写本批已观察结果。

## 运行静态检查

从仓库根执行 `python -B -m unittest discover -s tests -p test_v280_inputs.py -v`。集成后的 9 项检查已实际通过；它只证明输入导出、夹具结构和路径约束，不是路由或笔记行为验收。导出器不自动判断任意自然句子或材料是否隐藏答案，仍需人工审阅。
