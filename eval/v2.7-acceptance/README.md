## 输入与判分边界

`cases.json` 有 12 道四科代表请求、6 道边界请求及 2 道错题闭环请求。输入定义保留 `fixture-only`，不是 20 项通过；实际采集和评分另存。只把 `prompt` 发送给测试模型，`reviewOnly` 留在评分侧。2026-10-18 的隔离 CLI 试跑被宿主策略阻止读取 Skill，未形成有效样本，见 [环境记录](model-preflight-20261018.json)。

这组输入用于定向验证知识点映射及输出约束；若预先选择 tutor，只能报告定向 Skill 行为，不能用来证明自然请求自动路由。逐项核对：

- ID 与题面是否匹配；多知识点题是否允许合理组合，不能把候选列表当唯一答案。
- 是否清楚显示待核，避免把 topicPath 当作官方大纲路径，或把 2025 年学校材料映射已核升级成 2027 年已核；上位主题不能冒充字段细节的原文依据。
- 用户只要提示/独立作答时是否延后可能泄题的详细依据。
- 未收录是否保留未知，非 408 是否避免强套索引。
- 原有讲解、错因证据、脚本/人工复核边界是否保持。

已有结构检查覆盖索引 Schema、重复 ID、四科与前缀、日期、已核必备来源、待核路径为空，以及不支持的教材章节字段。结构检查不能代替上述模型行为或来源事实核验。
