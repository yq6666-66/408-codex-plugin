## 1. 目标与范围

将现有以插件清单和 14 个 Skill 为中心的仓库，重构为只提供三个高频场景的 Agent Skills 项目。一份技能源码生成 Claude Code、Codex、Cursor 三种安装布局，三端共享知识规则、计算实现与验收题，不维护三套提示词。

首版默认只覆盖考研 408 四科：数据结构、计算机组成原理、操作系统、计算机网络。Claude 在本设计中特指本地 Claude Code；Cowork、Claude 云端及其他产品不包含在首版兼容声明中。

| Skill | 主责 | 不应误接的任务 |
| --- | --- | --- |
| `408-error-diagnosis` | 依据用户实际过程定位错误，区分观察与原因假设，给纠正动作和最小验证题 | 没有作答过程时不能编造用户错误；不默认建立跨日错题数据库 |
| `408-concept-followup` | 回答当前概念疑点，解释条件、边界和反例，按用户要求逐层提示 | 不强制反问或重讲整章，不提前揭示用户要求保留的答案 |
| `408-calculation-check` | 核对题面条件，独立复算，说明工具或人工复核结果及适用边界 | 不承诺四科所有题型均有脚本，不执行用户提供的任意代码 |

招生与真题搜索、数学/英语/政治、跨科计划、整卷模考、进度诊断、自动复测日历、Obsidian/Notion 写入退出新主线的默认发现、导出与安装。旧内容归档，不在新主线中继续并行维护 14 个可见入口。

## 2. 方案比较与选择

推荐 **标准 Skills 源码 + 导出器 + 统一安装器**。三端都支持 `SKILL.md`，导出只处理资源装配、安装目录和必要元数据，维护面最小。

备选一是保留三套原生插件包装，并从公共源码生成。它能继续支持各宿主 marketplace，但清单、客户端版本与发现规则的验证成本更高，不适合作为这次收敛的核心。

备选二是只发布三个通用文件夹、手动安装。结构最小，但不能满足统一安装入口与可验证升级要求。

首版选择推荐方案；原生插件市场包装如需恢复，另行作为薄包装实现，不能成为第四份技能正文或新的核心依赖。

## 3. 单一源码与导出结构

建议组织：

```text
src/
  skills/
    408-error-diagnosis/SKILL.md
    408-concept-followup/SKILL.md
    408-calculation-check/SKILL.md
  shared/
    knowledge/points.json
    knowledge/sources.json
    references/
    calculation/
skillset.json
tools/skills.py
tests/
eval/
legacy/
```

这是目标结构，不表示这些实现文件当前已经存在。`skillset.json` 只登记版本、三个 Skill 的标识与资源依赖；每项信息只有一个维护位置。`SKILL.md` 的公共 frontmatter 保留 `name`、`description`，必要时使用标准 `metadata`；不把某一宿主的工具权限、命令展开语法或子 Agent 配置写进共用正文。

`src` 是需要装配的作者源码；安装器不得把未装配的源码目录直接作为安装产物。导出时将每个 Skill 所需的知识规则和脚本装配到该 Skill 自己的 `references/`、`scripts/`，使任意一个导出 Skill 都可单独安装。

导出物不得依赖 `../../references`、固定仓库层级、`.codex-plugin/plugin.json` 标记或品牌命名的用户配置目录来定位资源。共享文件的生成副本允许出现在多个产物中，但只能从同一源码生成，禁止手改生成文件。

| 目标 | 项目级产物布局 | 用户级安装位置 | 附加元数据 |
| --- | --- | --- | --- |
| `claude` | `.claude/skills/<skill>/` | `~/.claude/skills/<skill>/` | 首版不添加 Claude 专属行为字段 |
| `codex` | `.agents/skills/<skill>/` | `~/.agents/skills/<skill>/` | 可生成可选的 `agents/openai.yaml`，不改变公共正文 |
| `cursor` | `.cursor/skills/<skill>/` | `~/.cursor/skills/<skill>/` | 首版不转换为 `.mdc` rules |

Cursor 还可能发现兼容目录中的技能。同一安装作用域已存在相同技能时，安装器先核对内容与来源：相同内容复用，内容不同则报告冲突，不在多个兼容目录静默复制出重名入口。首版安装命令一次只指定一个平台，导出可以一次生成三个平台。

三种导出包的公共技能正文和资源内容应相同；目录前缀及已声明的可选宿主元数据除外。

## 4. 每题知识点依据

知识点标签不是知识依据；用户题面来源、参考答案来源和所用规则的依据分别记录。用户只贴出题目，不能据此声称所用定义来自某本教材。

每题至少说明：

1. 知识点名称与稳定标识，如 `os.memory.fifo`。
2. 实际使用的规则、定义或公式。
3. 适用条件与关键约定。
4. 依据类型、真实存在的来源位置及核对状态。

索引尚未覆盖的知识点使用 `pointId: null`，保留真实名称和规则并将依据标为待核验，不编造已登记标识。首版索引围绕验收题与现有五类计算能力建立，不把覆盖整份大纲当作首版完成条件。

默认回答可以只增加一行“知识点依据”，不强制每题输出 JSON 或长模板。需要导出时，机器结构包括 `pointId`、`pointName`、`rule`、`conditions`、`source.kind/title/locator/verification`；题面自身的 provenance 独立存放。

允许的依据层次：

- 用户实际提供并已读到的规则材料：注明用户材料、版本或可见定位，不补造页码。
- 已实际核对的原始教材、课程或标准：注明标题、章节/节号或直接链接，核对状态只覆盖实际读到的内容。
- 项目整理的规则卡：来源类型明确写“项目整理”，不能称官方大纲或教材原文。规则卡包含原创简述、条件和少量验证例，不打包教材全文。
- 尚无可核对出处：明确“外部依据待核验”，可继续给出有条件的推导和复核，但不得编造书名、页码或已读取声明。

来源定位必须可解析。校验器检查知识点标识、资源定位与来源状态结构，模型验收另查规则是否支持实际解题，不能用“引用文件存在”代替知识正确性。

## 5. 计算校验的真实能力

首版复用现有经测试的计算逻辑，暴露的支持清单仅为 Cache 直接映射/全相联、FIFO/LRU 页面置换、FCFS/RR 调度。全相联的替换规则、RR 同时到达和时间片边界的队列约定必须显式说明；题目约定不同时不能直接套用结果。现有脚本没有 SJF 或通用网络计算能力，不作相应自动校验承诺。

优先提供只读的参数输入和结构化状态/结果输出；HTML 演示不是校验前提。计算逻辑与 CLI 分开，沿用有意义的边界、状态与独立数值回归测试。没有脚本支持的题型可人工复核，输出明确区分“脚本校验”“人工复核”“条件不足”。

脚本不可用或被宿主守卫拒绝时，不改名、复制或更换解释器绕过。工具成功声明必须对应本轮真实调用与返回结果，不因本地安装了脚本就宣称已核验。

## 6. 统一工具入口

继续使用现有 Python 工具链，新增一个入口 `tools/skills.py`。以下是待实现的命令契约：

```text
python tools/skills.py export --platform all
python tools/skills.py install --platform claude --scope project --project <目标目录>
python tools/skills.py install --platform codex --scope project --project <目标目录>
python tools/skills.py install --platform cursor --scope project --project <目标目录>
python tools/skills.py verify --platform codex --scope project --project <目标目录>
```

`--scope user` 显式选择用户级目录，不需要 `--project`。默认不自动安装到全局，不要求账号、API Key、MCP 服务或运行后台进程。核心三个场景离线可使用；联网仅用于用户需要的来源补查，不是每道题的必经步骤。

安装先装配、验证，再写目标目录；只管理这三个技能。更新前备份原有受管理文件，未变化的安装保持幂等，遇到用户修改或来源不明的同名目录报告冲突。失败不留下半套新文件，不改宿主安全配置，不删除其他技能或笔记。导出与安装按完整相对路径清单校验，拒绝路径穿越和越界符号链接。

## 7. 迁移与版本

本次为能力与安装接口的重大收敛，建议以 `3.0.0` 开发候选管理，正式发布和标签另按既有门禁处理。

先完成新源码、三端导出和校验，再将旧入口及不再使用的源码归档到不参与新构建和发现的 `legacy/`。旧标签与备份继续可恢复，旧记录数据不作迁移或删除。归档的准确文件清单在实施迁移前形成可审查差异，不执行强制覆盖或改写已有版本标签。

新的根目录文档只介绍三个场景、统一安装和知识点依据，清楚标注旧插件用户的迁移步骤。安装新 Skill 不等于自动卸载已经安装的旧插件；存在旧入口时给出明确迁移提示，避免同名或相近技能重复激活。

本轮设计不再新增 ZCode、WorkBuddy 的原生包装维护任务；这些历史适配随旧版归档。GitHub 仓库重命名、云端同步和原生 marketplace 发布不阻塞首版技能重构。

## 8. 验收与交付

工程验收：

- 三种产物均只含三个可发现 Skill，命名与公共 frontmatter 有效。
- 公共正文和资源跨平台一致，每个导出 Skill 的所有相对引用均在自身目录内解析。
- 知识点和依据定位无悬空引用；缺来源、缺条件和用户材料的处理有负例。
- 计算支持清单与实际实现一致，关键结果、初态、边界及调度约定有独立数值测试。
- Windows/Ubuntu 的导出清单与归档可重复，安装具备幂等、备份、冲突和失败恢复测试。

行为验收以少量有区分力的场景为主：二分查找不收缩的实际错误过程；没有作答时不得虚构错因；FIFO 命中为何不刷新队列的概念追问；提示模式不泄答；16 位地址/64 B 块/256 行直接映射得到 tag/index/offset 为 2/8/6；FIFO 固定串 9 次缺页；网络时延题以人工复核标注单位；无外部来源不编造教材页码；脚本被禁用时如实降级。

结构校验、实际模型行为和真实客户端发现分别报告。Claude Code、Codex、Cursor 各需确认三技能发现与触发、引用读取、工具允许/拒绝时的状态；没有实际客户端通道就保留未验收，不能将 YAML 通过写成跨平台运行通过。

交付物为三份平台包、统一导出/安装/验证入口、三份精简 Skill、知识规则与出处索引、针对性测试及验收记录。新主线不以大量 Skill 数量或通用连接器数量作为完成指标。

## 9. 格式依据与未决版本边界

- [Agent Skills 规范](https://agentskills.io/specification)：`SKILL.md`、frontmatter、技能目录命名与相对资源规则。
- [Claude Code Skills](https://code.claude.com/docs/en/skills)：本地技能格式、安装目录与 Claude 特有扩展。
- [Codex Skills](https://learn.chatgpt.com/docs/build-skills)：`.agents/skills`、可选 `agents/openai.yaml`。
- [Cursor Skills](https://cursor.com/docs/skills)：原生技能目录、兼容发现与仓库导入约束。

上述官方文档于 2026-10-16 核对。最低客户端版本仍需在实施验收时实际探测；首版不依赖尚未在本机验证的新 Agent Plugins 根清单功能。现有 `.claude-plugin/marketplace.json` 是旧 ZCode 适配的一部分，不能当作已完成 Claude Code Skills 支持的证据。

设计自检：三个场景互相有明确边界；公共正文不分叉；原始题面与规则依据分开；工具支持清单没有扩张；旧模型记录不改绑新产物；未把未实施的命令或未运行的客户端描述为已通过。
