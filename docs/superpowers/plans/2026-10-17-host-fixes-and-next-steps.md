## 已落地的优化

- README 改为按宿主说明触发条件，去掉自然语言必然触发的通用保证；ZCode 的显式 planner 成功与普通请求 0/4 分开表述。
- Cursor 记录带 `github.com/` 的地址与用户报告边界；ZCode 给出固定提交的本地目录安装；WorkBuddy 明确配置目录与新会话要求。
- 安装器说明明确 `install_local.py install` 面向 Codex，运行于多个操作系统不等于替其他客户端安装。
- 新增 `scripts/audit_host_trace.py`，只读分析 ZCode 的 role/part JSONL，绑定输入 SHA-256，区分普通请求/显式选择/定向工具测试，按 callID 去重并保留调用状态。它不执行日志命令、不读取技能正文、不判断回答正确性。
- 增加 14 项回归测试，覆盖基础模型直接答题、内联 Python、失败调用、重复/部分状态、调用身份冲突、其他插件同名技能、用户引用的工具事件、非法输入及输入文件不被修改。另通过 3 项测试发现检查、18 项仓库契约测试和仓库六项校验。

工具支持范围仅是已经取得的 ZCode 导出格式；没有为 Cursor/WorkBuddy 猜造解析规则。上述测试不能证明客户端自动路由已修复。

## 新定位线索

提示题 `97b75fa2` 的原始模型 I/O 确认为 `claude-haiku-5-5`，工具清单含 `Skill`；保存的模型消息有 tutor 名称和路径，未出现 tutor 中文 description 或正文。Skill 工具说明指向 system-reminder 中的可用技能列表。该会话仍未调用 Skill。

可以确认技能入口在该次模型输入中可见，不能据此认定完整发现信息已正确传递，也不能仅凭一次样本把原因归为描述缺失或模型能力。需要同模型、同题面、同版本的显式选择对照。先不通过修改全部 Skill 描述或全局配置碰运气。

按结果选择修复点：

| 观察 | 下一步处理 | 可宣布的结果 |
| --- | --- | --- |
| 显式 tutor 正常，普通请求不选技能 | 对照技能发现信息与模型设置；必要时在独立测试环境只改变一个变量 | 显式链路可用；自动选择仍有缺口 |
| 显式选择后仍无法加载 tutor | 检查实际传入名称、宿主登记与路径，取得失败原文后做最小修复 | 受影响名称/路径修复且原请求复测通过 |
| tutor 已加载，但共享引用或脚本定位失败 | 对照已安装树和真实失败路径，修复对应解析或安装说明 | 仅声明已复测的路径通过 |
| tutor 选择人工推导且如实说明 | 按讲解与计算正确性评分；工具链另开定向请求 | 不能把未运行脚本直接当作讲解失败 |
| 守卫拒绝命令 | 保留拒绝，检查人工降级回答；误判形成可复现记录 | 不通过关闭守卫或改写执行方式绕过 |

若修复会改变插件文件，须重生成验证器证据和 ZIP，并绑定新的行为记录；不能继续用旧树哈希冒称新包通过。
